# AutoService — самостоятельная разработка

Офлайн-программа для небольшого российского автосервиса: один пользователь,
один компьютер Windows. Объясняй результаты по-русски простыми словами.

## Авторизация и источники
10 ноября 2026 пользователь согласовал самостоятельное выполнение этапов плана:
разработчик сам читает код, реализует функции, проверяет, исправляет ошибки,
создаёт локальные контрольные версии и поддерживает документы.
Не требуй копировать задания и отчёты между ChatGPT и Codex.

Перед работой прочитай `docs/STATE.md`, `docs/ROADMAP.md`, `docs/requirements.md`
и `docs/decisions.md`; затем нужные части кода и `docs/architecture.md`.
Текущее состояние кода и запущенные проверки важнее старого отчёта.
`docs/source/` — сохранённые материалы 8 ноября: источник истории, не актуальный
статус. Устаревшие указания «сейчас только проектирование/каркас» не ограничивают
согласованную разработку. Решения пользователя имеют приоритет над документами.

## Цикл работы
1. Проверь Git и изменения пользователя. Не сбрасывай, не прячь и не перезаписывай их.
2. Возьми следующую готовую задачу из ROADMAP; сначала исправляй регрессии.
3. Реализуй законченную небольшую функцию, самостоятельно выбрав обратимые
   технические детали. Не расширяй продукт за рамки согласованных требований.
4. Запусти относящиеся к изменению тесты, Ruff и проверку форматирования.
   Изменения UI проверяй реальным запуском Qt и просмотром снимка окна.
5. Исправь найденное; обнови STATE, ROADMAP и реестр решений.
6. Сохрани проверенные собственные изменения Git-коммитом и отправь текущую
   рабочую ветку в закрытый origin после проверок. Не включай посторонние изменения,
   базы, копии, секреты или данные клиентов. Пользователь повторно это не подтверждает.
   Перед push проверь новые файлы и URL origin; не применяй force push.
   При ошибке отправки сохрани локальный коммит и сообщи о несинхронизированной версии.
7. В длительном поручении продолжай следующие готовые задачи без запроса
   «можно продолжать?». На контрольной границе сообщи проверенный результат.

Задача готова, когда работает пользовательский сценарий, данные сохраняются
после перезапуска, проверки пройдены, нет ложных заглушек и обновлены документы.
Если тест невозможно выполнить, сообщи об этом, а не объявляй успех.
Работай последовательно: один писатель в репозитории и базе. Не запускай вторую
автоматизацию или параллельного разработчика поверх незавершённых изменений.

## Когда нужен пользователь
Собирай существенные продуктовые вопросы вместе в `docs/OPEN_QUESTIONS.md`.
Не выдумывай реальные интервалы ТО, образцы TXT, реквизиты и ответы владельца.
Отсутствующий ввод блокирует только соответствующую задачу; делай доступные задачи.
Не спрашивай о размещении файлов, запуске тестов и обычных исправлениях.
Публикация, платные сервисы, отправка сообщений и работа с реальными данными
не разрешены автоматически. Запросы доступа платформы соблюдай.

## Версии сборок

Перед каждой новой сборкой с изменениями увеличивай номер версии приложения.
Для обычных правок увеличивай последнее число, например с 0.5.17 до 0.5.18.
Проверь, что новый номер совпадает в приложении, свойствах EXE, имени ZIP
и вложенной папке. Сохраняй отдельный архив для каждой версии.

## Архитектура и данные
Python 3.13, PySide6 / Qt Widgets, sqlite3, pytest, Ruff, Git.
Без сервера, обязательного интернета, React, Electron, Docker и облака.
UI: `app/ui/`; бизнес-операции: `app/services/`; схема и снимки: `app/database/`.
Рабочая база: `%LOCALAPPDATA%/AutoService/autoservice.sqlite3`, отдельно от кода.
Импорт модулей не создаёт базу, не запускает окно и не меняет файлы.
Обновления SQLite — транзакционные, версионированные, с копией до миграции.
Не удаляй/не пересоздавай рабочую базу для исправления ошибки.
Неизвестную/новую схему оставляй без изменений. Не понижай версию схемы.
TXT-оригиналы не изменяй. Тесты и снимки — только вымышленные данные и временные БД.
Не коммить базы, импорты, экспорты, копии, персональные данные и секреты.
12 ноября пользователь явно разрешил подключить закрытый GitHub-репозиторий
Lev1313/AutoService и сохранять туда проверенные версии. origin:
https://github.com/Lev1313/AutoService.git. Подробности: docs/GITHUB.md.
Это разрешение относится к этому закрытому репозиторию. Не меняй его на публичный,
не отправляй в другие remote и не меняй права доступа без отдельного указания.

## Проверки
Из корня проекта:
- `.venv/Scripts/python.exe -m ruff check .`
- `.venv/Scripts/python.exe -m ruff format --check .`
- `.venv/Scripts/python.exe -m pytest`
При недоступном системном временном каталоге задай pytest новый отдельный
`--basetemp` внутри `artifacts/`; не используй каталог с пользовательскими файлами.
Проверка UI и резервных копий не должна открывать рабочую базу.

## Общение
Коротко: что сделано, что проверено, что осталось и какое решение действительно нужно.
Удобство оценивает пользователь; доступные технические проверки делай сам.
Не обещай фоновую работу после завершения чата без реально включённого механизма
продолжения. В STATE сохраняй точку продолжения.
