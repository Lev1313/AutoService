# AutoService

Бесплатная офлайн-программа для небольшого автосервиса в России: один пользователь,
один Windows-компьютер. Центральная сущность — автомобиль с историей ремонтов.
Объясняй изменения и результаты по-русски.

## Источники и границы
- Требования: `docs/requirements.md` (предварительный документ).
- Решения и состояние: `docs/architecture.md`, окружение: `docs/environment.md`.
- Сейчас реализуется только каркас. Не добавляй неподтверждённые функции,
  бизнес-таблицы и зависимости. Уточняй существенные продуктовые решения.

## Архитектура
- Python, PySide6 / Qt Widgets, стандартный sqlite3, pytest, Ruff, Git.
- `main.py` — вход, `app/bootstrap.py` — сборка приложения; `app/ui/` — интерфейс,
  `app/database/` — база, `app/services/` — операции вне интерфейса.
- Никаких веб-серверов, Electron, React, Docker или облачных зависимостей.
- Рабочая база: `%LOCALAPPDATA%\AutoService\autoservice.sqlite3`, отдельно от кода/exe.
- Импорт модулей не должен создавать базу, запускать окно или менять файлы.

## Изменения и данные
- Сначала находи и читай нужный код. Делай небольшие понятные изменения.
- Сохраняй обратную совместимость SQLite. Изменения схемы — версионированные,
  транзакционные миграции с проверкой сохранности данных и резервной копией.
- Не удаляй и не пересоздавай пользовательскую базу для исправления ошибок.
  Не понижай версию схемы; неизвестный формат оставляй без изменений.
- Не используй настоящие клиентские данные в тестах, демонстрациях и Git.
  Тестовые базы создавай только во временных каталогах.
- Не коммить базы, персональные данные, импорты, экспорты, копии и секреты.
- Не публикуй репозиторий и не создавай remote без разрешения пользователя.

## Интерфейс и проверка
- Светлый простой интерфейс, русский текст, компактные таблицы, Tab и горячие клавиши.
  Учитывай масштабирование Windows. Заглушки честно обозначай.
- Демонстрационные автомобили вымышлены и не записываются в рабочую базу.
- После изменений самостоятельно выполни:
  `.venv\Scripts\python.exe -m ruff check .`,
  `.venv\Scripts\python.exe -m ruff format --check .`,
  `.venv\Scripts\python.exe -m pytest`.
- Для логики и исправлений добавляй содержательные тесты. При изменениях UI
  проверяй запуск и навигацию. Не заявляй о пройденных проверках без запуска.
- Сначала исправляй и проверяй результат; затем предлагай пользователю оценить окно.
