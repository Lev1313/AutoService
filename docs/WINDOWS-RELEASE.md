# Сборка и проверка AutoService для Windows

## Локальная сборка 0.5.11

Подготовлена в `artifacts/release-0.5.11`: ZIP, PDF-руководство и SHA256SUMS.txt.
Из распакованного ZIP пройдены оба этапа диагностики, включая сервисный лист,
его повторное открытие и печать в PDF. Проверены окно документа и 5 страниц
руководства. GitHub Release для этой версии не публиковался.
[Изменения и проверки 0.5.11](RELEASE-0.5.11.md).

## Опубликованный выпуск

[AutoService v0.5.10](https://github.com/Lev1313/AutoService/releases/tag/v0.5.10) содержит
переносимый ZIP для Windows x64, PDF-руководство и контрольные суммы. Для воспроизведения
опубликованной версии используйте тег.

Распакуйте весь ZIP в новую папку и запустите `AutoService.exe`. Оставьте `_internal`
и `Инструкция.txt` рядом с EXE. Программа открывает рабочую базу, а F1 выводит инструкцию.
PDF-руководство и лицензии входят в ZIP. [Инструкция для пользователя](OWNER-GUIDE.txt).

## Повторить сборку

Подготовьте Windows x64 и окружение Python 3.13 по [инструкции](environment.md).
Установите `requirements-build.txt` поверх `requirements.txt`. Скрипт рассчитывает
номер по `pyproject.toml` и пишет в новый каталог.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe tools/build_windows.py --output artifacts/release-check
```

Результат — `dist/AutoService`, переносимый ZIP, PDF и `SHA256SUMS.txt`. Для сборки
Setup добавьте `--compiler 'C:\путь\к\ISCC.exe'`. PDF формируется из
`docs/OWNER-GUIDE.txt` системным Arial. Отдельно
собрать его можно командой `./.venv/Scripts/python.exe -m tools.make_print_guide --output artifacts/guide`.
Для исходников и старых установочных выпусков см. [дорожную карту](ROADMAP.md).

Сборка ограничивает `PATH` и проверяет, что рядом с Qt не оказалось внешней ICU.
`manifest-sha256.json` перечисляет файлы программы и их хеши. Клиентские базы, резервные
копии, настройки владельца и исходные архивы TXT хранятся вне дистрибутива.

## Проверка программы после упаковки

Распакуйте новый ZIP в отдельную папку. Запустите диагностику в двух процессах с одним
выделенным тестовым каталогом. Каталог для первого запуска должен быть новым.

```powershell
.\AutoService.exe --self-test 'C:\тесты\autoservice-release'
.\AutoService.exe --self-test-reopen 'C:\тесты\autoservice-release'
```

В `release-check.json` проверьте `stage=passed` и `frozen=true`. Сценарий использует
вымышленные данные и проверяет миграцию старой схемы до v7, копию и восстановление,
машины и клиентов, связь записи на ремонт, звонки и ТО, TXT, PDF и вывод на печать в PDF.
Дополнительно проверьте обычный запуск в отдельной папке данных и инструкцию по F1.

Для **полного выпуска с Setup** есть `tools/verify_windows.ps1 -ReleaseDirectory <папка>
-TestDirectory <новая папка>`. Он проверяет запуск, установку, обновление, удаление и
сохранность данных. При существующей установке владельца нужен изолированный тестовый
Setup с другим AppId и аргументами `-TestInstaller` и `-TestApplicationId`.
Тестовый Setup применяется лишь на отдельной папке и отдельной базе.
