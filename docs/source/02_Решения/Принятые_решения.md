# Реестр решений (не смешивать принятое и предложенное)

## УТВЕРЖДЕНО пользователем
- **D-001** (2026-11-08): вместо облачной ERP — **офлайн Windows-программа без платного сервера**, работающая на **одном компьютере владельца**.
- **D-002**: владелец — единственный пользователь, хотя в автосервисе трудится ещё несколько человек. Не делать обязательный многопользовательский режим.
- **D-003**: приоритет календаря — **кому и когда позвонить для приглашения на ТО**, а не только загрузка ремонтных постов. Дополнительная запись на ремонт допустима.
- **D-004**: прогноз ТО должен учитывать **и дату, и пробег** автомобиля. Не подменять фактический пробег прогнозом.
- **D-005**: клиенты и история существующего автосервиса должны импортироваться из **его прежних TXT-файлов**, которые предоставят на стадии разработки; сейчас есть только фотографии.
- **D-006**: важнейший принцип — **простота для человека, привыкшего к Блокноту**; не заставлять отмечать многочисленные этапные статусы.
- **D-007**: **утверждён вид упрощённой карточки ремонта**: дата, пробег, свободный текст, общая стоимость, кнопка «Завершить ремонт». Возможность простого сохранения незавершённой записи.
- **D-008**: вести проектную документацию централизованно и **не терять отложенные идеи**, хранить их отдельно для будущих версий.

- **D-009** (2026-11-08): нужны **оба формата квитанции** — простой (общее описание ремонта и итоговая сумма) и подробный (работы и запчасти по отдельным позициям с ценами). Подробные позиции не обязательны для простой квитанции; конкретный бланк и реквизиты ещё не согласованы.

## ПРЕДЛОЖЕНО, НЕ УТВЕРЖДЕНО ОТДЕЛЬНО
- **P-001**: стек Python + PySide6 + SQLite (хорошо согласуется с офлайн Windows, но выбор стека можно пересмотреть).
- **P-002**: 4 основных раздела: Главная, Клиенты, Календарь, Документы.
- **P-003**: время звонка прогнозируется как минимальный срок ТО минус заданный запас дней, с ручной корректировкой.
- **P-004**: два простых состояния ремонта — текущий и в истории; промежуточные статусы отсутствуют.
- **P-005**: документы — PDF/печать из карточки ремонта с раскрываемой детализацией; способ открытия и печати ещё предложен, наличие простого и подробного форматов утверждено в D-009.
- **P-006**: автоматические напоминания не превращать в уведомления/звонки по сети без согласования.
