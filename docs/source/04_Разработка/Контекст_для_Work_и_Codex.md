# Контекст для нового сеанса ChatGPT Work / Codex

## Задача
Продолжить **проектирование**, не писать весь код сейчас, пока пользователь не попросит. Работаем над очень простой **офлайн Windows-программой автосервиса** для одного владельца, несколько сотрудников на самом сервисе, на одном ПК. Замена многолетней базы TXT и бумажных заметок.

## Неотменяемые требования
- Удобство человека, привыкшего к обычному Блокноту. Минимальный ввод, без множества статусов.
- Утверждённая карточка ремонта: **дата, пробег, свободный текст, общая стоимость, «Завершить ремонт»**; отдельно «Сохранить» для текущей заметки.
- Главный календарь — **кому звонить и приглашать на ТО**, с учётом даты и пробега, а не исключительно расписание ремонтных постов.
- Должен быть **импорт папки исторических TXT** с несколькими визитами в одном файле и сохранением оригиналов. Реальные файлы обещаны позже.
- Клиенты/автомобили/история, простые квитанции/заказ-наряды/печать; шаблон ещё обсуждается.
- Сервер, интернет, смартфон и платные подписки не нужны.
- Идеи из backlog не забывать; не добавлять их в стартовый интерфейс без причины.

## Где истина
`README.md` → `STATUS.md` → `02_Решения/Принятые_решения.md` → файлы в `01_ТЗ/` → backlog. Файлы представляют текущее состояние проектирования на 8.11.2026, а не полностью согласованное ТЗ.

Подробно и просто спроектировать модуль квитанций: реальные бланки, формат, минимальный путь из карточки ремонта в документ, PDF, печать и законные ограничения. Обновлять файлы и CHANGELOG после следующих решений.

## Правила для будущего разработчика
Не переписывать контекст с нуля. Не считать предварительную идею принятой. Не усложнять UX ради «красивой архитектуры». Если нужна дополнительная структура в базе, она не должна превращаться в обязательные поля на экране.
