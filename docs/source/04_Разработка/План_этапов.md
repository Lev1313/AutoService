# План проекта от функционального ТЗ до внедрения

## Сейчас — только проектирование
**Этап 0.** Собрать и согласовать требования; упростить пользовательские сценарии; завершить проектирование документов; записать открытые вопросы. Не начинать код «наугад».

## Когда начнём разработку
**Этап 1. Демонстрационный макет UI.** Главная с напоминаниями, поиск, карточка авто, минимальная карточка ремонта, кнопка квитанции. Проверить вместе с владельцем, убрать лишние действия.

**Этап 2. Основа приложения.** Windows desktop, SQLite, создание/редактирование клиента и автомобиля, история пробега, минимальные ремонты, надёжное сохранение и тесты.

**Этап 3. Календарь ТО.** Отдельные циклы по работам, расчёт даты и пробега, задача на звонок, перенос, обработка, избегание дубликатов.

**Этап 4. Документы.** Шаблон по реальному бланку сервиса, PDF, печать, проверка итогов и редактирования. При необходимости подробнее структурировать позиции.

**Этап 5. TXT-импорт.** После получения оригиналов: анализ форматов, парсинг, пробный dry run, превью, защита от дубликатов, архив оригинального текста, массовый импорт.

**Этап 6. Пилот.** Обкатка в реальном сервисе сначала на тестовых и копиях данных; фокус на скорости, понятности, распечатке, возврате из backup.

**Этап 7. Релиз.** Установочный пакет для Windows, инструкция на одну страницу, проверенный механизм бэкапа, сценарий обновления БД.

## Готовность MVP (черновой checklist)
- [ ] Можно создать клиента и машину за минимальное число действий.
- [ ] Можно найти машину по госномеру/телефону.
- [ ] Ремонт можно записать в четыре поля; после завершения он в истории.
- [ ] Напоминание о ТО учитывает дату и пробег; плохие данные не дают ложный уверенный прогноз.
- [ ] Сегодняшние и просроченные звонки не теряются между запусками.
- [ ] Нужный документ печатается и открывается повторно.
- [ ] TXT-папка импортируется с просмотром сомнительных данных и без порчи исходников.
- [ ] Бэкап и восстановление проверены на тестовой базе.
- [ ] Владелец выполнил основные действия без подсказок.

## Ограничения проекта
Без обещаний 100% импортируемости до исходных файлов; без заявлений о юридической пригодности квитанции без проверки; без облака и онлайн-рассылок по умолчанию.
