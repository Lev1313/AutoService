# GitHub и работа с двух компьютеров

[Lev1313/AutoService](https://github.com/Lev1313/AutoService) — закрытый репозиторий.
Ветка по умолчанию — `main`. Для продолжения текущей работы используйте
`codex/autoservice-0.5.17`. Теги фиксируют исходники конкретных
выпусков. [v0.5.10](https://github.com/Lev1313/AutoService/releases/tag/v0.5.10) содержит
проверенный ZIP для Windows, PDF-руководство и SHA-256.

## Продолжить на ноутбуке

Для новой копии выберите пустую папку и войдите в GitHub аккаунтом с доступом к репозиторию.

```powershell
git clone --branch codex/autoservice-0.5.17 https://github.com/Lev1313/AutoService.git
cd AutoService
```

Для существующей копии сначала посмотрите, что изменилось на ноутбуке.
Если рабочая папка чистая, выполните `git fetch origin`. Переключитесь на
`codex/autoservice-0.5.17` и обновитесь командой `git pull --ff-only`.
Если локальной ветки ещё нет, используйте
`git switch --track origin/codex/autoservice-0.5.17`.
При расхождении веток сначала сравните изменения обоих компьютеров.

Порядок настройки Python и запуска приведён в [README](../README.md).
[Точка продолжения](STATE.md) показывает состояние проекта и оставшиеся задачи.

## Облачные копии на ПК сервиса

На 22 ноября 2026 рабочая сборка — **0.5.20**. Правки механика, аварийное
восстановление и проверка PDF и TXT уже в ветке. На учебных данных проверили
отправку в Google Drive API после обрыва связи, скачивание, сверку SHA-256
и восстановление на втором компьютере. Личный режим OAuth **Personal** также
проверен с рабочим ключом восстановления. Рабочие данные и ежедневное
расписание на ПК сервиса ещё не подключены.

Войдите в GitHub под аккаунтом с правом записи в закрытый репозиторий и откройте
[черновик AutoService 0.5.20](https://github.com/Lev1313/AutoService/releases/tag/untagged-6df7c782fd4720ddc932).
Для ПК сервиса нужен `AutoService-0.5.20-work-backup-setup.zip`. В черновике
также лежат отдельная переносимая сборка и контрольные суммы обоих архивов.

1. Перенести на ПК сервиса ZIP и отдельно JSON клиента Google **Personal**
   (на исходном ПК файл `client_secret_…json`, скачанный 22 ноября в 16:11 МСК,
   из проекта `vertical-backup-515513-m7`). Для настройки достаточно этих файлов,
   если рабочая база уже есть. Учебный файл `.age` и документы Word не нужны.
2. Войти под обычным пользователем Windows механика. В старой версии сделать
   резервную копию базы и закрыть программу. Старую папку программы можно оставить.
   Распаковать новый комплект целиком в отдельную папку.
3. Открыть `AutoService-0.5.20\AutoService.exe` из комплекта. На действующем ПК
   проверить, что видны знакомые автомобили и ремонты. На чистом ПК восстановить
   отдельно перенесённую рабочую копию. Первый запуск при необходимости обновит
   схему базы. После обновления старая версия может перестать открывать эту базу.
   Закрыть 0.5.20 после проверки.
4. Запустить `Setup-backups.cmd`, выбрать JSON. В браузере войти в личный
   Google-аккаунт владельца и подтвердить доступ приложения. В комплекте уже есть
   AutoService 0.5.20, rclone, age и открытый ключ шифрования.
5. Сверить путь к базе и папку `FoltzMaster-work-backups`. Когда владелец готов
   отправить рабочие данные, ввести `YES`. Программа сверит первую загрузку,
   затем включит расписание при входе в Windows и ежедневно в 19:00 по времени ПК.
   Другое время можно задать параметром `-DailyAt`.
6. Убедиться, что первая копия подтверждена, файл `.sqlite3.age` виден на Google
   Диске и следующее запланированное выполнение прошло. Детали проверки приведены
   в [руководстве по Google Drive API](GOOGLE-DRIVE-BACKUP.md).

Флешка с файлом `FoltzMaster-Recovery/recovery-key.txt` нужна для расшифровки
при восстановлении. Для продолжения с ноутбука также держите отдельно OAuth JSON,
доступ к Google-аккаунту и резервную копию рабочей базы, если её нужно перенести.
В GitHub хранятся код, инструкции и установочные архивы. Зашифрованные копии
базы хранятся на Google Диске.

## Сохранить готовый этап

1. Проверьте ветку, локальные изменения и точный адрес `origin`.
2. Запустите подходящие проверки. Включите в коммит только файлы текущего этапа.
3. Отправьте коммит в закрытый `origin` обычным `git push`. Сверьте удалённую ветку с локальной.

GitHub хранит код, документацию, теги и файлы опубликованных выпусков. ZIP прикрепляется
к выпуску, а рабочая база переносится через резервную копию `.sqlite3`
в настройках AutoService. Для входа Git использует настроенный Git Credential Manager.
