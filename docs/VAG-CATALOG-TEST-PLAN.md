# Подсказки моделей, регламенты VAG и тестовые файлы

Дата: 17 ноября 2026. Статус: только план, реализация не начата.
Текущий выпуск остаётся 0.5.1, схема базы — v6.
Пользователь сообщил, что около 90% работы механика приходится на VAG.
Поручение: разобраться с Serisi, продумать регламенты для всех моделей концерна
и добавить генерацию тестовых файлов. До отдельной команды не менять программу,
каталог, схему, рабочие данные или установщик; не начинать загрузку регламентов.

## 1. Исправление качества подсказок — первый приоритет

Причина найдена: названия Serisi уже содержатся в исходном MIT-справочнике
app/assets/car_models.json, а не появляются из-за ошибки ввода.
У BMW это строки 200–207, у Mercedes-Benz — группа строк 1150–1187.
Serisi — турецкое обозначение серии; для русской программы оно не подходит.
VehicleCatalog читает исходные строки и дополняет их сохранёнными моделями.

План исправления:
- Проверить весь встроенный список на локализованные слова, дубли, смешение моделей,
  поколений и модификаций; сначала BMW и Mercedes-Benz.
- Сохранить исходный снимок, лицензию, commit и хеш. Добавить проверенный слой
  исправленных названий и соответствий, чтобы обновление источника было проверяемым.
- Для BMW использовать понятные названия вроде «1 серия», «3 серия»; для Mercedes
  проверять принятое название каждой модели, например «A-класс», «C-класс».
  Не выполнять общую замену слова Serisi для всех марок.
- Разобрать записи вроде «3 Serisi (M3)»: обычная серия и M-версия не должны
  автоматически считаться одной моделью. Исключения проверить по производителю.
- Учесть Serisi, ранее сохранённое в машинах: оно сейчас снова попадает в подсказки
  из локальных моделей. Для известных соответствий исправлять представление подсказки
  и поиск, убирать эквивалентные дубли; хранимую строку карточки не менять без выбора.
- Новые подсказки показывать без Serisi. Свободный ввод сохранить. Уже записанные
  автомобили не переименовывать автоматически; исправление старой карточки —
  отдельное явное действие с просмотром результата.
- Проверить поиск по привычным вариантам, фильтр марки, отсутствие дублей,
  сохранение своих названий и работу каталога внутри готового EXE.

Готовность: русские подсказки проверены в настоящем окне Windows; пользовательские
названия и история машин сохраняются; происхождение каталога документировано.

## 2. Регламенты ТО VAG — цель и границы охвата

Цель — справочник для всех автомобильных моделей концерна, включая прежние
поколения. Полнота определяется не количеством названий моделей, а проверенным
охватом годов, модификаций, рынков и условий обслуживания.

Сначала составить таблицу покрытия: марка → модель → поколение → модельные годы →
двигатель/коробка/привод → рынок → источник → статус проверки.
Статусы различать: проверено, частичный охват, нужен источник, не применимо.
Отсутствие найденного интервала не означает, что обслуживания не требуется.

Предлагаемая очерёдность наполнения:
1. Volkswagen, Audi, Škoda, SEAT/CUPRA и Volkswagen коммерческие автомобили:
   сначала самые частые у механика поколения, затем остальные.
2. Porsche, Bentley, Lamborghini и остальные относящиеся к согласованному
   автомобильному охвату марки — отдельные источники и проверка применимости.

Это порядок работы, а не сокращение цели до популярных моделей. Перед началом
наполнения зафиксировать перечень марок и диапазоны лет. Список частых автомобилей
уточнить у механика во внешнем листе вопросов; в приложение вопросы не добавлять.
Не обещать полный охват до заполнения и проверки таблицы покрытия.

## 3. Источники и возможность загрузки

Основа — материалы производителей: официальные таблицы обслуживания, руководство
по техническому обслуживанию и подходящие руководства владельца. У каждого
регламента сохранять документ, раздел/страницу, редакцию, дату проверки и рынок.
Поиск в интернете — способ найти источник, а не подтверждение самого интервала.

По официальной странице Volkswagen Group erWin на дату плана:
- Доступ к ремонтной и сервисной информации — платный, для бизнеса, по лицензии.
- erWin не предоставляет поток данных через API. Подключение одной кнопкой
  с автоматической массовой выгрузкой нельзя считать готовым способом загрузки.
- Охват erWin включает VW легковые/коммерческие, Audi, Škoda, SEAT, CUPRA и Bentley;
  у Lamborghini на этой странице указана только диагностическая информация.
  Источники для Porsche и недостающих марок/лет надо проверять отдельно.
- Возможность доступа для сервиса в России, сохранения офлайн и включения данных
  в установщик требует отдельной проверки условий конкретного источника.

Возможные способы наполнения после проверки источников:
- Проверенный отдельный пакет справочника, если источник допускает такое использование.
- Локальное добавление документов/правил самим сервисом из доступных ему материалов.
  Чужие документы и данные конкретных VIN не включать в исходники и общий выпуск.

Автоматическое распознавание PDF может подготовить черновик, но не подтверждает
интервалы. Перед публикацией правила сверяются с оригиналом и применимостью.
На этапе планирования ничего не покупать, не регистрировать и не скачивать массово.

## 4. Как это будет работать для механика

Предлагаемый сценарий:
1. В карточке автомобиля открыть подбор регламента ТО.
2. Подтвердить поколение/модельный год, двигатель, коробку и другие данные,
   которые нужны конкретному источнику. VIN может помочь при наличии доступа
   к официальным данным; сам по себе VIN в нынешней программе их не расшифровывает.
3. Получить подходящие варианты с источником и списком условий применимости.
   При неполных данных показать, что именно нужно уточнить, без назначения
   произвольного «среднего» регламента модели.
4. Просмотреть работы, интервалы и основания; подтвердить применение к машине.
5. Ввести известные дату и пробег последнего выполнения. Если история неизвестна,
   сохранить это явно, не считать работы выполненными сегодня.
6. Пользоваться существующими ТО и звонками; выполненные работы отмечать явно.

Техническое предложение: отдельный версионируемый офлайн-справочник, независимый
от клиентской базы. Для выбранной машины сохранять снимок применённых правил,
источник, редакцию и собственные изменения механика. Обновление справочника
предлагает различия и сохраняет действующие циклы, историю и ручные корректировки.

Минимальная применимость правила: марка, модель/поколение, модельные годы,
код двигателя, код/тип коробки, привод, рынок, комплектация/PR-коды и режим
обслуживания — по необходимости исходного документа. Не все поля обязательны
для каждой операции. Совпадение названия модели не считается достаточным.

Данные операции: проверка или замена; первый и последующие интервалы; месяцы/км;
условие наступления срока; точка отсчёта; ограничения и исключения; источник.
Заводское правило и рекомендация механика отображаются раздельно и имеют автора.

## 5. Что нужно доработать в текущем расчёте ТО

Сейчас Maintenance поддерживает повторяющийся интервал в месяцах и/или километрах,
опорные дату/пробег, явное выполнение и задачи звонков. В машине пока нет
структурированных данных двигателя, коробки, поколения или рынка.

До подключения реальных регламентов необходимо:
- Поддержать различие первого и последующих сроков и корректную точку отсчёта.
- Разделить проверку по состоянию и обязательную замену.
- Представлять условные правила и переменный сервисный режим без превращения
  их в выдуманный одинаковый интервал. Неподдерживаемое условие показывать явно.
- Проверить правила календаря и пробега, единицы измерения и границы применимости.
- Сделать безопасную миграцию с копией, если понадобятся изменения клиентской схемы.
- Проверить, что смена регламента не создаёт дубли звонков, не отменяет отказы
  и не переписывает ранее подтверждённое обслуживание.

Детальную схему данных и вид формы выбирать после пробного разбора нескольких
разных официальных регламентов и обсуждения удобства с механиком.

## 6. Генерация файлов и наборов для тестирования — отдельная задача

Сделать воспроизводимый генератор полностью вымышленных данных для ручных
проверок и автоматических сценариев. Использовать имеющиеся тестовые примеры
и диагностику; реальные клиентские файлы и базу генератор не читает.

Состав наборов:
- TXT для импорта: UTF-8, BOM, CP1251, UTF-16, разные переводы строк, пустые
  и неполные записи, длинный русский текст, несколько ремонтов и машин.
- Пограничные/ошибочные файлы: неоднозначные даты, неизвестные поля, нулевая
  и неизвестная стоимость, повтор файла, частичный импорт, изменённый оригинал,
  ошибки кодировки, повреждение и обрыв файла.
- Демонстрационные базы: клиенты с несколькими машинами, ремонты/удаление,
  достоверный и перенесённый пробег, ТО, звонки и результаты, документы.
- Наборы для проверки экспорта TXT/Excel, PDF, резервных копий и восстановления:
  ожидаемые количества, связи, точные суммы, тексты и контрольные суммы вложений.
- Наборы VAG: несколько модификаций с одинаковым названием, неполные параметры,
  разные рынки, первый/повторный срок, отсутствие источника и обновление правил.
  Тестовые интервалы явно вымышлены и не попадают в справочник реальных регламентов.
- Малый набор для показа, обычный для проверок и большой для оценки скорости.
  Размеры и целевое время определить до нагрузочной проверки.

Каждый набор содержит описание сценария, параметры генерации, фиксированную дату,
seed, перечень файлов/хеши и ожидаемое поведение, включая ручное подтверждение
сомнительного импорта. Проверочные ожидания задавать отдельно от проверяемого
алгоритма. Одинаковые параметры дают одинаковые исходные данные; различающиеся
служебные метаданные описать отдельно.

Генерация идёт только в новый выделенный каталог и отдельные тестовые базы.
Не перезаписывать рабочие/демонстрационные пользовательские данные. Базы, PDF,
экспорты и большие сгенерированные наборы не коммитить; сохранять генератор,
описания и небольшие проверенные вымышленные примеры по правилам проекта.

Готовность: набор можно создать одной командой и проверить по инструкции;
ошибочные примеры дают ожидаемые предупреждения, повторный импорт не дублирует
данные, перезапуск/backup/restore сохраняют связи и оригиналы.
Синтетические TXT проверяют механизм и не заменяют будущую проверку реального архива.

## 7. Порядок после отдельной команды начать

| Этап | Результат |
|---|---|
| Q1 | Исправленный и проверенный справочник подсказок |
| Q2 | Генератор и описанные тестовые наборы, основа дальнейших проверок |
| V1 | Подтверждённые источники, условия использования и таблица покрытия VAG |
| V2 | Проверенный формат правил на нескольких существенно разных регламентах |
| V3 | Подбор в карточке, подтверждение и безопасное применение к существующим ТО |
| V4 | Наполнение по очередям с явным отчётом покрытия и экспертной сверкой |
| V5 | Проверка Windows, инструкции и выпуск после проверок |

Открытые решения перед наполнением: частые модели/годы у механика, доступные
официальные источники, диапазоны лет и приоритет марок; способ выдачи данных
при ограничениях источника. Платные подключения и расходы отдельно согласуются.
Финансы и склад в этот план не входят. До команды начать — только документы.
