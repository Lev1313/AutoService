# Технические решения

## Среда и интерфейс
Python 3.13.1, PySide6 / Qt Widgets, Fusion, светлая тема; зависимости зафиксированы.
Главное окно: QListWidget + QStackedWidget. Порядок: Автомобили, Звонки, Календарь, Финансы, Настройки.
При запуске открыты Автомобили. Ctrl+F выбирает страницу по объекту; обновление звонков
не зависит от номера раздела в меню.
Формы автомобилей и ремонтов — отдельные диалоги; UI не содержит SQL.
Длинная запись читается целиком под таблицей истории. Данные QLabel — PlainText.
Рабочие действия доступны с клавиатуры; закрытие изменённой формы требует решения.

## SQLite v5
Путь: `%LOCALAPPDATA%/AutoService/autoservice.sqlite3`.
`app_metadata` определяет приложение; `PRAGMA user_version` — версию схемы.
- contacts: самостоятельные контактные лица.
- vehicles: стабильный ID, данные машины, текущий контакт, поле архива на будущее.
- vehicle_contacts: история замены контакта машины.
- repairs: машина, дата, свободный текст, целые копейки, признак завершения.
- odometer_readings: дата, километры, источник, достоверность, ссылка на ремонт.
- maintenance_plans: индивидуальные интервалы, опорные дата/км, номер текущего цикла.
- maintenance_events: явно подтверждённые выполнения ТО и необязательная связь с ремонтом.
- call_tasks: одна задача на (правило, цикл), вычисленная/ручная дата, состояние.
- call_attempts: журнал результата и следующей даты звонка.
- vehicle_call_preferences: отказ от приглашений для будущих правил этой машины.
- document_settings: введённые владельцем реквизиты.
- document_drafts: редактируемая необязательная детализация ремонта.
- documents: отдельные неизменяемые снимки, номера и история экземпляров.
- document_files: исходные PDF-байты и SHA-256, включены в резервную копию базы.
- import_sources: исходные байты TXT, контрольная сумма, кодировка и декодированный текст.
- import_fragments: точные диапазоны исходника, проверенные поля и привязка к ремонту/машине.
- import_paths и import_batches: происхождение и отчёты завершённых импортов.
- repairs.origin/state_known/undated_km: импорт и неизвестные состояние/дата без подстановок.

Контакты и ремонты не удаляются каскадно. Операции с контактом/машиной и
ремонтом/замером выполняются транзакционно. Пользовательского удаления пока нет.
Изменение контактных данных одной машины создаёт новый контакт и связь, если они
отличаются от выбранного существующего контакта. Остальные автомобили не меняются.
Сумма/пробег NULL отличаются от нуля. Деньги не проходят через float.
Unicode-поиск нормализуется в Python; стандартный SQLite lower не подходит для кириллицы.

## Обновление и копии
Новая база создаётся сразу на v5. Для прежних v1–v4 до миграции создаётся отдельный снимок
через SQLite backup API; без успешной копии миграция отменяется. Все DDL — в транзакции.
Чужая идентичность, отсутствующие таблицы и более новая схема приводят к отказу,
а не сбросу базы. Проверяются откат неудачной миграции и сохранность данных.
Ручная копия — через Настройки. Существующий файл копии не перезаписывается.
Восстановление принимает проверенные снимки v1–v5: integrity_check,
идентичность, версия, нужные поля и foreign_key_check. До замены сохраняется текущая база.
Старая копия сначала мигрирует в отдельном временном каталоге, оригинал остаётся
неизменным. Только после успешной проверки сохраняется текущая база и заменяется снимок.
Автоматической очистки сохранённых копий нет.

## Календарь
Месяцы добавляются с учётом последнего дня месяца и високосного года.
Порог км сравнивается с достоверным замером; будущие/недостоверные замеры не используются.
Прогноз отталкивается от последнего замера и оставшихся километров: средний темп
из истории либо явно введённая владельцем оценка за год. Источник оценки показан.
Из доступных дат выбирается ближайшая; если данных нет, задача остаётся «Уточнить срок».
Ручная дата приоритетна. Расчёт не изменяет результаты звонков и номер цикла.
Цикл меняется только по явной отметке «ТО выполнено» с подтверждением пользователя.
Повторное выполнение по тому же ремонту защищено уникальным ограничением.

## Разработка
Тесты: pytest, QtTest, только временные базы. Ruff: ошибки и форматирование.
Рабочая папка: `C:/Projects/Autoservice`. Материалы разработки хранятся рядом с кодом.
`docs/source/` — исторические источники. Основные документы: requirements, decisions,
ROADMAP, STATE, OPEN_QUESTIONS. Локальный Git — контрольные версии без публикации.
Общая Goal включена пользователем в текущем чате. Отдельного расписания и облака нет.
Windows-выпуск: PyInstaller onedir + Inno Setup, версия 0.2.1. Данные не включены
в установщик и не удаляются при деинсталляции. Обычный запуск держит QLockFile
до выхода, чтобы два процесса не восстанавливали/редактировали одну базу одновременно.
Проверка выпуска и ограничения: WINDOWS-RELEASE.md; инструкция: OWNER-GUIDE.txt.

## Документы
ReportLab 5.1 формирует A4 с встраиваемыми системными шрифтами Arial (Windows).
QtPdf/QPdfView показывает фактический PDF; QtPrintSupport открывает системную печать.
Печатаются страницы исходного PDF, с учётом выбранного диапазона. Проверен вывод через
PDF-принтер, а затем одна страница на физическом HP LaserJet MFP M139-M142 по USB.
Пользователь подтвердил читаемость и отсутствие обрезки. Другие принтеры не проверены.
Предпросмотр не сохраняет документ и не резервирует номер. Создание фиксирует снимок
данных и PDF в одной транзакции; ошибка рендеринга откатывает создание и номер.
Изменение ремонта/машины/реквизитов не меняет сохранённые байты. Их целостность проверяется.
Цены и итоги в копейках; количества в тысячных, округление строки ROUND_HALF_UP.
Расхождение итога строк со стоимостью ремонта требует явного решения. Ремонт не меняется.
Описание, позиции и реквизиты экранируются перед PDF-разметкой. Внешние ресурсы не загружаются.

## TXT-импорт
UTF-8/BOM и UTF-16 BOM определяются непосредственно; Windows-1251 предлагается с предупреждением.
Другие кодировки (DOS-866, KOI8-R, UTF-16 LE/BE) выбираются явно, без замены повреждённых байтов.
Один файл ограничен 10 МБ; ошибки чтения показаны и входят в отчёт при успешном импорте других файлов.
Консервативный разбор: полные даты в начале строк, явно подписанные поля. Даты без года,
разные суммы и нечёткий пробег остаются неизвестными. Любая подсказка подтверждается владельцем.
Предпросмотр не меняет базу; перед подтверждённой записью создаётся копия. Весь выбранный пакет
записывается транзакционно. Файл после просмотра повторно сверяется с прочитанными байтами.
Архив хранит байты целиком и точные фрагменты, включая переносы строк; их можно просмотреть
из карточки ремонта и выгрузить отдельной копией, не перезаписывая существующий файл.
Повтор защищён хешем файла и пересечением диапазонов, в том числе после переименования/разделения.
Похожие ремонты из изменённого источника требуют отдельного подтверждения. Совпадения авто не сливаются.
Ранее подтверждённая однозначная привязка файла предлагается при частичном продолжении;
неоднозначные случаи остаются для ручного выбора. Разные кодировки одного сохранённого источника не смешиваются.
Неизвестная дата хранится как NULL и не подменяется сегодня при редактировании. Пробег без даты
сохраняется у ремонта, но не становится достоверным замером. Импортированные замеры по умолчанию
не подтверждены; исправление только текста не делает их достоверными. Статус ремонта тоже не угадывается.
Импорт не создаёт платежи, циклы ТО и задачи на звонки по свободному тексту.
Проверен механизм на синтетических примерах; качество на реальном архиве пока не установлено.
